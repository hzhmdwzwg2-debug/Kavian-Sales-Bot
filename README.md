# Kavian Sales Bot — پایه اجرایی 0.1

سامانه فارسی مدیریت تیم فروش، مسیر بازاریاب‌ها و گزارش ویزیت؛ طراحی‌شده برای **Telegram native Serverless (Beta)**.

> **وضعیت:** کد و رابط کاربری اولیه آماده شده است؛ هنوز به بات واقعی وصل یا در Telegram منتشر نشده است. قبل از استفاده واقعی باید روی حساب تلگرام شما استقرار، مهاجرت پایگاه داده و آزمون عملی انجام شود.

## قابلیت‌های این نسخه

- Telegram `/start`: ایجاد درخواست ورود در وضعیت **غیرفعال** تا مدیر اجازه بدهد.
- مدیریت پویا: ایجاد تیم، افزودن/انتقال سرپرست یا بازاریاب، غیرفعال‌سازی بدون حذف تاریخچه.
- ثبت مشتری، پیشنهاد مسیر تاریخ‌دار و مرتب، بررسی و تأیید یا برگشت توسط سرپرست.
- ثبت ویزیت مثبت، منفی، تعطیل، انجام‌نشده و خارج از مسیر؛ مبلغ سفارش در **ریال**.
- داشبورد خلاصه با تفکیک مجوزهای مدیر، سرپرست و بازاریاب.
- ثبت تاریخچه عملیات مدیریتی (audit log).
- Mini App موبایلی راست‌چین که از API داخلی `Telegram.WebApp.Serverless.call` استفاده می‌کند.

## معماری

- `tgcloud/schema.js` — طرح دیتابیس SQLite داخلی تلگرام.
- `tgcloud/handlers/message.js` — ورود اولیه بات.
- `tgcloud/endpoints/` — توابع سروری مینی‌اپ، با اعتبارسنجی نقش روی سرور.
- `tgcloud/lib/auth.js` — کنترل نقش و اعتبار ورودی.
- `tgcloud/lib/bootstrap.js` — اختصاص مدیر اولیه **فقط از طریق CLI خصوصی**.
- `miniapp/` — رابط HTML/CSS/JS بدون نیاز به فریمورک.
- `dist/` — خروجی ساخت مینی‌اپ؛ به‌صورت خودکار هنگام build ایجاد می‌شود.

## مراحل استقرار در GitHub Codespaces

1. ZIP را استخراج کنید و فایل‌ها را به مخزن خصوصی GitHub منتقل کنید (پوشه پروژه را در ریشه مخزن قرار دهید).
2. در Codespace همان مخزن، ترمینال را باز کنید؛ `npm install` را اجرا کنید.
3. از BotFather → بات → Serverless → CLI Access، **Access token** را کپی کنید؛ از چت یا GitHub برای انتقال آن استفاده نکنید.
4. در ترمینال خصوصی Codespaces، `npx tgcloud login` را اجرا کنید و Access token را فقط در همان ترمینال وارد کنید.
5. `npm run build` سپس `npx tgcloud push` و سپس `npx tgcloud migrate` را اجرا کنید. قبل از تأیید مهاجرت، خلاصه تغییرات را مرور کنید.
6. **فقط بعد از مهاجرت**، مدیر اولیه را با شناسه عددی تلگرام خودتان ثبت کنید:

   ```bash
   npx tgcloud run lib/bootstrap '{ telegramId: 123456789, name: "مدیر کاویان" }'
   ```

   عدد مثال را با Telegram user ID واقعی خودتان جایگزین کنید. این دستور را فقط در ترمینال خصوصی متصل به بات خودتان اجرا کنید. هرگز این ماژول را به endpoint عمومی تبدیل نکنید.
7. خروجی `npx tgcloud push` آدرس Mini App را نشان می‌دهد. در BotFather، آدرس Mini App را به دکمه منوی بات وصل کنید.
8. در تلگرام به بات `/start` بفرستید، سپس از منو مینی‌اپ را باز کنید. به‌ترتیب تیم، کاربران، مشتریان، مسیرها و ویزیت‌ها را بسازید.

**مهم:** فایل `.tgcloud/credentials` یا Access token و Bot Token نباید در GitHub commit شوند. این پوشه در `.gitignore` است؛ برای Codespaces بهتر است دسترسی مخزن خصوصی و Secret‌های محیط را محدود نگه دارید.

## محدودیت‌های نسخه 0.1

- هنوز Telegram deployment عملی و آزمایش End-to-End انجام نشده است.
- خروجی اکسل، واردکردن مشتریان از اکسل، یادآوری زمان‌بندی‌شده، ثبت سفارش کالایی، اصلاح گزارش و گزارش ماهانه در این نسخه پیاده نشده‌اند.
- ثبت مسیر تکراری برای یک روز و بازاریاب محدود شده است؛ حذف و درج مجدد توقف‌ها در نسخه بعد باید اتمیک شود تا خطای شبکه داده نیمه‌کاره نگذارد.
- به‌روزرسانی نقش و جابه‌جایی تیم از طریق `team_memberships` سابقه را نگه می‌دارد، اما گزارش تاریخی عملکرد تیم‌ها در نسخه بعد دقیق‌تر می‌شود.
- اطلاعات مشتریان به کاربران فعال (از جمله بازاریاب‌ها) برای ثبت خارج از مسیر نشان داده می‌شود؛ در فاز بعد می‌توان محدوده دسترسی مشتری را محدود کرد.
- نسخه اول شاخص تحقق مسیر را بر اساس مشتریان یکتای مسیر تأییدشده محاسبه می‌کند؛ «تعطیل» و «مراجعه‌نشده» ویزیت انجام‌شده نیستند.
- در صورت استفاده تولیدی، باید کنترل همزمانی ثبت ویزیت، نسخه‌گذاری مسیر، محدودیت حجم گزارش، پشتیبان‌گیری و بازیابی آزمون شوند.
